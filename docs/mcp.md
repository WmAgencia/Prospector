# Prospector MCP (optional)

MCP is disabled unless `MCP_ENABLED=true` and `MCP_PUBLIC_URL=https://YOUR-CANONICAL-HOST/mcp` are configured. The canonical URL must be HTTPS with exactly `/mcp`, no query, credentials or fragment. Configure the same public host in the frontend gateway; never derive OAuth issuer or audience from forwarded request headers.

Connect an MCP client to that URL. Protected-resource discovery advertises the authorization server, dynamic client registration and PKCE S256. Register HTTPS callback URLs exactly. Authorization requires signing in through the existing private dashboard link, reviewing scopes and clicking Authorize. The approval form uses a five-minute single-use nonce plus a separate HttpOnly Secure SameSite=Strict cookie. The gateway must preserve `ps_mcp_approval` cookies on `/oauth/*` and the original canonical Origin on approval POSTs. It must never attach a dashboard session to public `/mcp`, registration or token requests.

The token endpoint accepts form-encoded authorization-code and refresh grants. Send `resource` equal to the canonical MCP URL on both grants. Codes expire after five minutes; access tokens after one hour; refresh tokens after thirty days and rotate on use. Scopes are `prospector:read`, `prospector:prepare`, and optional `prospector:outreach`; scope escalation is rejected. Dashboard cookies never authenticate MCP requests; use the issued Bearer access token.

The stateless Streamable HTTP endpoint supports JSON responses, initialize, ping, tools/list and tools/call. Protocol versions: 2025-11-25 and 2025-06-18. POST with Accept including application/json and text/event-stream; GET returns 405 because no server SSE stream is offered. Include MCP-Protocol-Version after initialization. An Origin header, when present, must equal the canonical public origin.

Tools: `prospector_status` returns aggregate pause/count/job status; `prospector_prospects` returns at most 50 basic company records without phone numbers or conversation bodies; `prospector_prepare` previews at most 20 selected leads through existing documented opt-in/suppression checks. Preparation performs no sends, queue writes or consent grants. With separately granted `prospector:outreach`, `prospector_enqueue` accepts 1–20 UUID leadIds plus explicit `approve: true` and delegates to the existing consent/suppression/unknown-delivery guarded queue. This authorizes actual worker delivery at the existing interval. `prospector_queue` reads aggregate queue status; `prospector_cancel` requires `approve: true` and cancels pending items only. OAuth approval clearly warns that outreach access permits actual sending; it never grants consent to leads. Read/prepare scopes cannot call these tools. No owner-agent/admin tools are exposed.

Public routes: `/mcp`, `/.well-known/oauth-protected-resource`, `/.well-known/oauth-protected-resource/mcp`, `/.well-known/oauth-authorization-server`, `/oauth/register`, `/oauth/token`. Browser session routes: GET `/oauth/authorize`, POST `/oauth/approve`. Registration is open to public OAuth clients; deployments should apply edge request/body/rate limits to registration and token routes. Approval state is in process memory: restarting or changing replicas during authorization requires restarting that flow (use one backend replica or sticky routing).

Validation: `node --test tests/mcp-http.test.mjs tests/mcp-server-smoke.test.mjs` uses temporary SQLite storage and an isolated local HTTP server, with no customer sends. The full-server smoke starts an empty temporary dashboard and checks canonical Origin routing. Outreach tests create only temporary fixture consent/queue rows and never start a worker.

Implementation references: [MCP authorization 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization) and [Streamable HTTP transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).
